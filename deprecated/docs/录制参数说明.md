# 录制参数说明
> 历史归档：正文中的操作和相对命令描述原版本；当前日常操作请使用根目录工作台。

> 本文中的命令、配置和资源路径均相对于软件包根目录 `miicamera-kit/`；辅助入口在 `test/`，旧方案入口在 `test/legacy/`。

日常录制只修改本目录的 **`录制参数.toml`**，再使用下面三个入口。初始模板是 NVIDIA H.265（HEVC）、p5、CQ30、GOP250、最多3个连续B帧，3840×2160、45 fps，录制1小时、每1小时分段。手动修改后以TOML和启动摘要为准。CQ30是可调整的试录起点，不代表已完成长录验收。

本轮实际容量、帧率及异常记录见 [CQ30试录结果](cq30-user-config-trial.md)。

## 三步使用

1. 用记事本打开 `录制参数.toml`，修改需要的值并保存。数值不带单位，文字保留英文双引号，布尔值写小写 `true` / `false`；`#` 后面是注释。不要重名添加同一个参数。**顶层参数必须放在 `[x265_params]` 和 `[imaging]` 之前**，否则会被当作表内参数。
2. 双击 **`test/检查录制配置.cmd`**，确认显示的编码器、质量、曝光、时长和保存路径。它只做离线语法、字段和参数组合检查，不打开相机，也不验证编码器能否启动、实际磁盘可用空间或持续吞吐。改好后双击 **`test/试录当前配置一分钟.cmd`**：只临时覆盖为60秒、每20秒分段，其他值均按当前文件执行，不改写配置文件。查看视频细节、帧率和记录状态。
3. 关闭 ImageView 的实时画面，双击 **`启动录制.cmd`**。它按当前文件执行，不再交互覆盖时长、分段或输出位置。窗口结束后查看本次目录的 `capture.json`；`status` 应为 `complete`。长录前逐步扩大试录时长，短录通过不能证明72小时连续记录可靠。

需要中止时按一次 **Ctrl+C**，等待文件收尾后再关窗口。主动中止会标记 `incomplete`；程序会尝试排空已接收的编码队列并收尾已有文件，不能把它当作完成原定时长，也不能保证断电或强制关窗口时文件完整。

该TOML配置只控制本工具的采集程序，**不会控制 ImageView**；镜头对焦、光圈和机位仍需人工调整。旧的“按推荐配置录制”“按官方参数CRF录制”等入口仍使用各自的旧 JSON，修改本 TOML 不会改变它们。

## 录制时实时预览

`启动录制.cmd` 和 `test/试录当前配置一分钟.cmd` 可在录制时打开实时预览。它使用录制程序的同一路采集流，不另开相机，也不启动 ImageView。开始前仍须关闭 ImageView 的预览/录像，最好退出 ImageView，以释放相机。

在根目录 `录制参数.toml` 的顶层（两个表之前）设置以下参数；已有行直接修改，不要重复添加：

```toml
preview_enabled = true
preview_fps = 5
preview_max_width = 960
```

`preview_enabled` 为 `true` / `false`；`preview_fps` 为整数1～10，默认5；`preview_max_width` 为整数320～1280，默认960。预览按整数倍降采样，实际宽度不超过设定上限。拖动调整预览窗口大小只改变显示，不改变采集或保存视频。它是低帧率监看画面；保存视频仍按所选配置采集、编码，选择4K45时仍保存完整3840×2160、45 fps视频，不因预览缩小或降帧。旧JSON配置未填写这些参数时默认关闭预览。

点击预览窗口关闭按钮，或在预览窗口按 **Q / Esc**，只关闭预览，录制继续。要停止录制，在录制CMD窗口按一次 **Ctrl+C**，等待视频写入收尾后再关CMD窗口；完整录满时还会逐段解码验证。已经运行的旧进程不能事后补开预览；待本次结束后，使用新入口再次启动才生效。

预览跟不上时只跳过预览帧，不丢弃待录制帧；预览不落盘原始帧，预览启动或显示失败也不会因此终止主录制。预览仍有资源开销，需在目标电脑试录，不能据此认定4K45或长录性能已通过验收。

## CMD进度与容量状态

到新电脑先双击 `客户电脑快速诊断.cmd`，可检查环境、编码器实际运行能力、4K合成速度，并在设备条件满足时按本配置做20秒分段试录。报告不会自动修改本配置。详见 [客户现场快速诊断](客户现场先看.md#到客户电脑先运行快速诊断)。

两个统一录制入口会在CMD/Windows Terminal中原地刷新同一块中文状态，不逐次追加刷屏；上方配置摘要保留，错误、收尾提示和最终结果保留在窗口中。窗口变窄时按宽度换行。输出重定向到日志文件或终端不支持刷新时，自动保留普通逐条文本，便于诊断。在 `录制参数.toml` 顶层设置以下参数；这是设置示例，已有行直接修改：

调整窗口宽度时，为避免误擦配置摘要，可能保留上一块状态一次；随后在新的位置继续原地刷新。重新打开工具并开始下一次录制后生效，已经运行的旧进程不会热更新。

```toml
status_enabled = true
status_interval_seconds = 2
```

`status_enabled` 为 `true` / `false`；`status_interval_seconds` 为整数1～60秒，默认2秒。状态和预览参数均在下次启动读取，不会热更新正在运行的进程。状态输出由独立工作线程处理，不让采集线程等待CMD输出。

录制阶段显示已录/剩余时间、时间进度百分比、实测fps、采集帧数、帧号缺口、编码队列、MKV总大小、磁盘可用空间，以及近期/平均近似Mbps；还显示已生成、结束写入和当前分段，以及预计总段数、预计还会新增的段数。分段估计受实际采集帧率影响：例如实测约45.2 fps、名义编码45 fps时，可能多出很短的尾段，不能把预计段数当作固定承诺。

注意区分 **录制中 → 收尾写入 → 逐段验证 → 完成 / 未完成**。录制时间达到100%只表示计划采集时间结束，仍须等待写入收尾和逐段验证进度；最终以 `capture.json` 的 `complete` / `incomplete` 为准。中止或异常留下的未完成文件不代表已通过完整解码验证。

近期与平均码率按MKV容器文件增长估算，不含CSV；约8 Mbps相当于1 MB/s。容器缓冲会造成近期值突增或暂时偏低，它不是编码器的精确瞬时码率，也不能代替最终文件检查。

`写入近1s均值 X.XX ms/帧（N帧）` 表示每次刷新时，过去1秒内完成的N次RGB图像写入编码程序输入管道的平均耗时。统计窗口固定1秒，与CMD刷新间隔独立；需要每秒看一次，可将已有的 `status_interval_seconds` 改为1。它包含管道写入时的阻塞等待，不含帧在队列中的等待和CSV写入，也不是显卡实际编码耗时或视频落盘耗时。45fps对应每帧约22.2ms的平均处理时间预算；均值持续偏高并伴随队列上涨才需要重点关注，偶发单帧变慢不等于已经丢帧。

过去1秒没有成功完成写入时显示“无完成帧”，不会用0ms或旧均值代替；若有一帧仍在写入，则另显示“当前写入已等 X ms”。按写入完成时间选取样本，一次耗时超过1秒的写入在完成时计入其完整耗时。此指标随新程序自动显示，下次启动录制生效。

## 常用改法

下面都是修改已有行，不是重复粘贴到文件末尾。改编码器后，即使某些质量字段暂时不生效，也应保留其合法值。

**H.265 NVIDIA CQ23 / CQ30 / CQ32**：保留以下组合，只将 `nvenc_cq` 改为需要的数字，例如23、30或32。

```toml
encoder = "hevc_nvenc"
rate_control = "quality"
nvenc_preset = "p5"
nvenc_cq = 30
gop_frames = 250
b_frames = 3
```

同一编码器和条件下，CQ或CRF数字越小通常质量越高、文件越大。CQ23、CQ30、CQ32应在相同光照和动作下比较毛发、轮廓与运动细节；**CQ30与CRF21没有等价换算关系**，也不能把官方软件的“质量100”直接当作任何CQ/CRF值。

**H.265 CPU CRF21 对照**：修改这些顶层行；现有 `[x265_params]` 保留。该表来自 `config/mouse-4k45-official-crf.json` 的编码信息对照方案。

```toml
encoder = "libx265"
rate_control = "quality"
x265_preset = "superfast"
crf = 21
gop_frames = 250
b_frames = 3
```

这条路径依赖CPU。本机已有4K45编码吞吐不足的记录，选择CRF21或复用官方样片参数不保证实时45 fps。程序遇到队列溢出会停止并标记未完成；不要直接用于未经验证的长录。

**H.264**：NVIDIA选择 `encoder = "h264_nvenc"` 并用 `nvenc_cq`；CPU选择 `encoder = "libx264"` 并用 `crf`。两种都必须同时改 `b_frames = 0`。本工具的 libx264 预设固定 `ultrafast`，不能通过 `x265_preset` 调整。

**时长、分段与保存盘**：例如录制8小时，每小时分段，保存到独立目录：

```toml
duration_hours = 8
segment_seconds = 3600
output_dir = "D:/MouseRecordings"
```

Windows路径建议用正斜杠；如用反斜杠，TOML双引号内要写成 `"D:\\MouseRecordings"`。`output_dir = ""` 表示自动选包外路径：在本仓库是 `private/source/data/camera-recordings`；将环境包单独搬走后，是包旁边的 `camera-recordings`。不要填相对路径，也不能保存到 `miicamera-kit` 内。每次自动创建新的记录目录，不覆盖旧记录。

**30 fps**：同时修改 `fps = 30`、`speed_level = 2`。45 fps对应 `speed_level = 4`。不要靠 `sdk_frame_rate_limit` 软件丢帧来替代速度档位。

**容量优先的码率模式**：只有确实需要约束码率时才切换，例如：

```toml
rate_control = "capped_vbr"
bitrate_mbps = 24
maxrate_mbps = 26
buffer_mbits = 52
```

此时CQ/CRF不生效，复杂画面可能损失细节。`libx265` 当前不支持此模式。启动前会按上限、时长和余量估算所需空间；估算仍不是完成记录的证明。

## 编码模式与生效范围

| `encoder` | 硬件/编码 | `quality` 模式 | 预设 | `capped_vbr` | `b_frames` |
|---|---|---|---|---|---|
| `hevc_nvenc` | NVIDIA H.265 | `nvenc_cq`；忽略 `crf` | `nvenc_preset` | 支持；忽略CQ/CRF | 0～3 |
| `h264_nvenc` | NVIDIA H.264 | `nvenc_cq`；忽略 `crf` | `nvenc_preset` | 支持；忽略CQ/CRF | 必须0 |
| `libx265` | CPU H.265 | `crf`；忽略 `nvenc_cq` | `x265_preset`、`x265_params` | 不支持 | 0～3 |
| `libx264` | CPU H.264 | `crf`；忽略 `nvenc_cq` | 固定 `ultrafast` | 支持；忽略CQ/CRF | 必须0 |

统一入口要求明确填写以上编码器，不接受 `auto`，避免自动回退后偏离所选方案。底层兼容接口仍接受 `auto`，不代表统一入口可以使用它。选择NVENC需要兼容的NVIDIA显卡和驱动；失败时应查看日志，不会在统一入口静默改用CPU。

`quality` 下 `bitrate_mbps`、`maxrate_mbps`、`buffer_mbits` 均不参与编码；`capped_vbr` 下CQ/CRF均不参与编码。当前验证器仍要求这些暂不生效的字段数值合法。

当前NVENC路径另固定使用 `rc=vbr`、`rc-lookahead=0`、`no-scenecut=1`、`forced-idr=1`；质量模式使用 `b:v=0` 和所选CQ值，码率模式改用所选目标/上限/缓冲。以上固定项不能通过新增TOML字段修改；未知字段会报错。libx264固定 `ultrafast`、关闭场景切换及开放GOP，最短关键帧间隔等于所选GOP。容器、像素格式及其他固定限制见文末。

## 全部普通参数

以下范围是本工具的配置检查范围，设备实际支持和实时性能还需启动及试录验证。

### 标识、输出与保护

| 字段 | 含义、单位与约束 |
|---|---|
| `schema_version` | 格式版本，只能1。 |
| `profile` / `description` | 方案名称（非空文字）/说明文字；用于存档，不改变画质。 |
| `duration_hours` | 计划采集小时数，>0且≤168，可用小数。 |
| `segment_seconds` | 每段名义视频秒数，整数1～86400；最后一段可不足此值。按编码帧数分段，不是精确墙钟切点。 |
| `output_dir` | 空字符串使用包外默认目录；否则须为包外绝对目录。 |
| `max_recording_gb` | 单次记录目录总量保护阈值，十进制GB，正数≤1000000；达到附近会报错停止并保留已有文件，状态未完成。可删除此行使用“不设总量阈值”的默认值；磁盘低空间保护仍保留。 |
| `keep_awake` | `true` 录制时请求Windows阻止自动睡眠；不能防止断电、重启、拔线或人为休眠。 |

`max_recording_gb = 950` 是停止保护，**不保证1TB磁盘能存满72小时**。CQ/CRF体积取决于运动、纹理、噪声及光照；保护检查和收尾也可能使体积超过阈值。程序另有固定10 GiB剩余空间保护。`capped_vbr` 还会检查计划预算与总量阈值是否冲突。

### 编码与码率

| 字段 | 含义、单位与约束 |
|---|---|
| `encoder` / `rate_control` | 见上表；码率模式为 `quality` 或 `capped_vbr`。 |
| `nvenc_cq` | NVENC质量值，整数1～51。 |
| `crf` | CPU编码质量值，整数0～51。 |
| `nvenc_preset` | `p1`～`p7`；通常越往后计算越多，改变后重新检查吞吐。 |
| `x265_preset` | `ultrafast`、`superfast`、`veryfast`、`faster`、`fast`、`medium`、`slow`、`slower`、`veryslow`、`placebo`；只作用于libx265。 |
| `gop_frames` | 关键帧间隔的最大/目标值，整数1～65535帧；250÷45≈5.56秒。 |
| `b_frames` | 最多连续B帧，整数0～3，受编码器限制。B帧不是额外插入的采集帧。 |
| `bitrate_mbps` | 目标码率，Mbps（每秒百万比特），不是MB/s。 |
| `maxrate_mbps` | VBV码率上限，必须≥目标码率。 |
| `buffer_mbits` | VBV缓冲容量，Mbit；与采集缓冲帧数不同。 |

三个码率字段均须为正数且≤1000000。**G250不是“一个I帧后250个P帧”**；启用B帧后GOP含I/P/B帧，场景切换或分段处可能提前出现关键帧。分段起点强制独立解码关键帧（IDR），因此实际GOP可缩短；libx265的场景切换、最短间隔等还受其高级参数影响。

### 相机采集与传输

| 字段 | 含义、单位与约束 |
|---|---|
| `width` / `height` | 当前只支持3840 / 2160。 |
| `fps` | 名义编码帧率，整数1～60；30/45分别强制匹配速度档2/4。其他值通过语法检查不表示相机一定可实现。 |
| `speed_level` | SDK速度档，整数0～4；45 fps用4，30 fps用2。 |
| `sdk_frame_rate_limit` | SDK软件限帧，整数0～60；0表示不设此限帧。非零可能丢弃源帧。 |
| `exposure_us` | 曝光微秒，整数1～5000000；12000=12 ms，1/90秒约11111。过长曝光会拖慢采集并增加运动模糊。 |
| `gain` | SDK百分数，整数100～65535；100=1倍，1016≈10.16倍。高增益可放大噪声并增加压缩体积。 |
| `frontend_buffer` / `backend_buffer` | SDK前/后端缓冲，分别为整数2～64帧；当前均16。不能用无限加缓冲解决长期编码不足。 |
| `usb_thread_priority` | USB接收线程优先级，整数0/1/2；当前2。 |

当前曝光12000、增益1016、白平衡5468/1163是**室内诊断对照值**，不是正式小鼠照明的固定推荐值。先保证光照和运动清晰度，再考虑降低增益，例如100；光照不足时直接改100会使画面变暗。换照明、夜间或红外条件后需重新检查曝光与成像。

### `[imaging]` 成像参数

此表与CQ/CRF无关，所选编码器都会应用。参数写入后读回核对，写入失败或读回不一致会停止；离线检查通过不证明SDK支持写入。

| 字段 | 含义、约束 |
|---|---|
| `bit_depth` / `binning` / `roi` | 当前固定8 / 1 / `"full"`，即8位、不合并像素、全画幅。 |
| `gamma` | 伽马，整数20～180；100表示1.00。 |
| `contrast` / `brightness` | 对比度/亮度，分别为整数-255～255。 |
| `hue` / `saturation` | 色相整数-180～180；饱和度整数0～255。 |
| `sharpening` | 锐化强度整数0～500，0关闭锐化。 |
| `white_balance_temp` | 白平衡色温SDK值，整数2000～15000。 |
| `white_balance_tint` | 白平衡色调SDK值，整数200～2500。 |
| `level_low` / `level_high` | 四通道色阶低/高端，均为4个0～255整数；每个低端须小于对应高端，默认 `[0,0,0,0]` / `[255,255,255,255]`。 |
| `denoise` | 可选整数0～100。TOML默认不写此行，加载器转为“未控制”，保持SDK现状，不代表关闭降噪。设备支持时才显式设置；不支持会停止。 |

TOML没有 `null`，不要写 `denoise = null`；要恢复“保持SDK现状”，删除该行或将整行注释掉。保留 `[imaging]` 时，除 `denoise` 外应保留整套字段，不能只留下想修改的几项。

## `[x265_params]` 高级参数速查

本表仅用于 `encoder = "libx265"`。现值用于复现样片的编码信息，不能保证与官方软件逐像素一致，也不能保证本机CPU达到4K45。普通调整优先使用CQ/CRF、预设、GOP和曝光；改变高级参数后应重新试录。`crf`、`keyint`、`bframes` 由顶层字段负责，不能在此表重复添加。

| 字段（当前值） | 含义 |
|---|---|
| `frame-threads = 1` | 同时进行帧级编码的线程数。 |
| `pools = 20` | 工作线程池配置；移到其他CPU后需按实际核数与负载检查。 |
| `ref = 1` | 运动预测可用的参考帧数量。 |
| `min-keyint = 25` | 最短关键帧间隔，帧数；不得超过顶层 `gop_frames`。 |
| `b-adapt = 0` | 自适应B帧决策方式；0关闭自适应。 |
| `rc-lookahead = 10` | 前瞻帧数，影响帧型决策、延迟和负载。 |
| `scenecut = 40` | 场景切换检测阈值。 |
| `ctu = 32` / `min-cu-size = 8` | 编码树单元最大/最小编码单元边长，像素。 |
| `rect = 0` / `amp = 0` | 矩形/非对称运动分区开关，0关、1开。 |
| `max-tu-size = 32` | 最大变换单元边长，像素。 |
| `tu-inter-depth = 1` / `tu-intra-depth = 1` | 帧间/帧内变换单元递归搜索深度。 |
| `me = 1` / `subme = 1` | 运动搜索算法编号/亚像素搜索精度等级。 |
| `merange = 57` | 运动搜索范围，像素。 |
| `weightp = 0` / `weightb = 0` | P/B帧加权预测开关。 |
| `sao = 0` | 样本自适应偏移滤波开关。 |
| `rd = 2` | 率失真优化搜索等级，影响计算量。 |
| `aq-mode = 1` / `aq-strength = 0` | 自适应量化模式/强度；强度0不施加此强度调整。 |
| `cutree = 1` | 编码单元树的时域质量分配开关。 |
| `open-gop = 1` | 开放GOP开关；分段仍强制独立起点。 |
| `b-pyramid = 1` | B帧参考层级开关。 |
| `strong-intra-smoothing = 1` | 强帧内平滑开关。 |
| `psy-rd = 2` | 视觉率失真优化强度。 |
| `deblock = "0,0"` | 去块滤波的两个偏移值，用英文逗号分隔的字符串。 |

高级参数校验只允许以上键，并检查非负整数形式；`aq-strength`、`psy-rd` 还接受非负小数，`deblock` 接受两个带可选负号的整数。**它没有完整检查x265各参数的语义范围或相互兼容性**；不要把“离线检查通过”当成任意数值均受支持。0/1开关也应保持0或1。

## 记录文件与核对

每次输出包含 `segment-0001.mkv` 等视频、对应 `*.frames.csv` 逐帧索引、`continuous.ffmpeg.log`、`profile-used.json` 和 `capture.json`。视频固定为MKV、8位YUV420、无音频；这些格式当前不能在TOML中切换。

`profile-used.json` 保存配置来源路径与SHA-256、解析后的完整参数（含本次试录覆盖）、实际编码器与生效编码设置、相机设置读回值。它同时保留暂不生效的配置字段，因此应以 `encoding_settings` 判断本次采用CQ、CRF还是码率模式。`capture.json` 保存状态、错误、分段、帧数与采集时间等元数据。

视频按设定帧率播放，不能单凭播放器显示45 fps判断源采集完整；实际采集时间看CSV，完成状态与帧率检查结果看 `capture.json`。`incomplete` 时保留输出和日志供核对，不应当作已验收的完整记录。
