# 官方 ImageView 录制流程

> 本文中的命令、配置和资源路径均相对于软件包根目录 `miicamera-kit/`；辅助入口在 `test/`，旧方案入口在 `test/legacy/`。

2026-10-25：用户确认原厂录像画质满足当前要求，后续以 **ImageView 自带录制**为主要方案。保持已认可的 **MP4／H.265、质量 100**，采用正常时间连续录像；不把旧脚本的 H.264 目标码率、GOP 或配置文件套入官方录像。

2026-10-26已定位兼容性问题：ImageView调用旧 `NV_ENC_PRESET_LOW_LATENCY_HP_GUID`，当前610.88驱动在 `nvEncGetEncodePresetConfig` 返回12／不支持的参数，随后硬件编码器创建失败，自动回退libx265。这是直接运行时证据；用户选择NVIDIA并没有操作错误。[NVIDIA公告](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/deprecation-notices/index.html)明确从590驱动起移除此预设。此次软件回退短片48.582秒只有1066个可解码帧，约21.94fps。**本机当前ImageView不能作为已通过的4K45硬件录像方案；预览45fps不代表录制45fps。** 需厂商升级编码组件；当前未发现比已安装版本更新的官方包，也没有有效官方NVENC CQ可供推断。

现有现代NVENC路径已在610.88驱动重新通过30秒4K直录：45.2268fps、1355帧，序号缺口／软件丢帧／缓冲满计数均0，四段450/450/450/5帧全部可解码。可通过 `test/legacy/试录H265一分钟.cmd` 做独立试录；此入口仍采用既有CQ23配置，不等于官方质量100，也不代表72小时验收。此次诊断使用高增益1016%、12ms曝光，视频约121.42MB；正式入口为100%、10ms，不应混淆。

## 操作步骤

1. 双击包内 `打开官方录制软件.cmd`。它与原 `test/legacy/打开相机预览.cmd` 都启动原厂 ImageView，不会自动开始录像。
2. 点击相机型号开始预览，核对 3840×2160、RGB24、实际帧率和画面。调焦、光圈在镜头上完成；曝光、增益和白平衡在现场光照下调整并记录。用户已调好的参数不应被旧脚本 JSON 覆盖。
3. 点击左侧「录像」或「捕获 → 开始录像」。首次及换电脑后用完整向导核对：MP4／H.265、质量 100、编码器、保存目录、正常时间倍率及时间限制。Time-lapse 区域的帧数／时间是延时摄影设置，不是分段设置；正常录像保持 ×1、不启用抽帧。以当前界面为准；快速录像会沿用上次设置，不能省略首次核对。
4. 录像保存到软件包外的指定目录。先录短片、正常停止并等待写盘结束，回看开头和结尾，核对时长、帧率、画质和大小，再延长到实际工作时长。
5. 记录相机与镜头、机位、照明、曝光、增益、白平衡、编码器、质量档、开始结束时间及现场操作。官方 MP4 不会由本环境包自动附带旧脚本的逐帧相机 CSV、`capture.json` 或参数快照。
6. 录像结束后保留原 MP4 并核对备份；日常直接使用原文件，避免为统一容器或码率而再次压缩。

录制时保持相机连接与供电，核对电脑睡眠和重启安排。当前语言资源存在“当预览/捕获视频时阻止进入休眠状态和运行屏幕保护程序”选项，但本轮没有改动该选项或验证它的实际行为。设备诊断脚本会打开相机，使用前先退出 ImageView；官方录像期间不并行运行 SDK 采集。

## 一小时分段与72小时录制

这两项仍需用当前原厂版本验证，不能从画质通过推定已经支持：

- 随包英文手册 PDF 第56页的录像向导说明，勾选时间限制后可设 1–86400 秒，到时停止。**设置 3600 秒本身不等于自动每小时新建文件。** 当前界面的实际输入范围和未勾时限时的上限也需要核对。
- 当前语言资源包含 `Batch Record／批量录像`、录像数量和间隔字段；但2026-10-25实看运行中的「捕获」菜单，仅显示捕获图像、定时捕获、开始录像和广播，没有批量录像入口。资源字符串不能证明当前版本能启用批量连续录制。
- 同日核对「选项 → 首选项 → 快速录像」及完整录像向导，确认有自动命名、沿用上次编码设置和单次时间限制，未见自动续录选项。当前向导保留 H.265、质量100、RTX 3070 GPU编码；时限未勾选、倍率×1。查阅界面后已取消，没有改变这些设置或启动录像。
- 2026-10-26补充：上述GPU选择是后来查看界面时的状态，不代表此前样片的实际编码器。`261025223957.mp4` 的编码信息SEI含x265的UUID及 `rc=crf crf=21.0` 等参数，强烈支持这份样片来自x265软件编码路径；播放器的RTX3070标识也不能用来确定编码设备。
- 官网资料和本地 SDK 未找到可控制 ImageView 内置 H.265 录像的公开接口；SDK 的 RAW/RGB 采帧不是原厂录像接口。可评估外部程序操作官方界面，让它每小时结束文件并重新开录，编码仍由 ImageView 完成，但两段间可能漏录。目前尚未开发或验证这一控制程序，不能据此承诺72小时无人值守。
- 自动续录、分段处是否漏录、掉线恢复和完整72小时稳定性均未验证。若厂商确认了适用的批录入口，应先做短时多段试验，再跨过实际一小时边界检查；有意设置的间隔应记入记录。
- 如需把已完成的大文件分成每小时片段，可使用已有工具做 **不重编码的切分**，保留原始文件。此举不额外压缩画质，但通常需要在关键帧附近切分，也不能降低录制过程中单个大文件中断的风险。本轮未执行文件切分或启动长录。

## 容量依据

用户确认质量为100的样片 `261025223957.mp4`：50.013秒、10,360,781字节、HEVC Main、3840×2160、平均约44.009 fps；按文件大小计算整段码率约1.66 Mbps。解码观察到关键帧间隔250帧、大量B帧。这只是该次文件的编码结果，不是已导出或已复现的全部原厂设置。

2026-10-26已从该样片提取部分实际编码参数：x265编码信息、CRF21、GOP250、B帧3、前瞻10、AQ强度0、CU-tree开启。按这些参数用当前x265重新编码前450帧，视频数据约1.410MB，官方对应视频包约1.413MB；并非必须调用原厂私有录像接口才能达到接近体积。不过输入已经被官方压缩，不能当作相机直录或画质等价证明；也不能将“质量100=CRF21”泛化到其他编码器和版本。试验说明见 [H.265试录与容量对比](hevc-recording-trial.md)。

按此样片速率算约0.75 GB/小时、72小时约54 GB，**仅作换算，不能作为小鼠日夜长录的容量保证**。先用正式机位、日夜光照和动物活动样片估算，留出空间余量；旧脚本的约907 GB启动门槛和950 GB停止保护不适用于 ImageView。

另一次明确选择NVIDIA、质量100的官方短录 `261026004706.mp4` 为48.582秒、100.10MB、约16.48Mbps。它与前片的场景和实际帧率不同，不能公平比较编码效率，但进一步说明官方输出不是固定约1–2Mbps。完整码流与运行采样保存在开发机包外 `private/qa/scratch/imageview-encoder-study-20261026/official-nvidia-live/`，不随迁移包分发。

## 迁移与来源

完整复制环境包，保留 `runtime/imageview/x64` 与上级语言、帮助资源的目录关系；在客户机重新核对官方设置并试录。客户电脑已有的显卡驱动、USB连接及保存空间也要确认。菜单7可校验软件包；菜单1打开官方软件，其余标为“脚本”的录像入口属于原方案。
