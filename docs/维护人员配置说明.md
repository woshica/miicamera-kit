# 维护人员配置说明

新版根目录「启动录制.cmd」启动本地浏览器控制页，并继续使用原有录制内核。日常流程见「操作员上手指南.md」。本页面向维护人员，修改编码或采集设置前，应停止录制并等待收尾和验证完成。

## 配置来源与首次初始化

优先使用已有 config/operator/。尚无该目录时，先兼容导入客户本机保留的根目录「录制参数.toml」；若没有该旧文件，则从 config/operator-template.json 创建配置。deprecated/录制参数.toml仅供旧工作流追溯，不是工作台的初始化来源。已有配置不会因模板变化而覆盖。导入保留采集、编码、时长、路径、曝光和增益，不用开发机配置覆盖客户设置。

导入只创建一个「现场当前方案」，它不表示现场画质已验证。客户原根目录 TOML 兼容导入时保持原样；初始化后修改 TOML 不会自动同步新界面。归档菜单使用 deprecated/ 中的旧配置。不要同时维护两套参数却假定它们始终一致。

## 三层配置

| 文件 | 职责 |
| --- | --- |
| advanced.json | 公共维护基线：分辨率、帧率、速度级别、编码器、质量、缓冲、成像等；不包含日常路径/时长/分段和方案曝光/增益 |
| daily.json | output_dir（包外绝对路径）、duration_hours（小时）、segment_minutes（分钟）、scheme（所选方案 ID） |
| schemes.json | 以方案 ID 为键，每项含 name、exposure_ms、gain_multiplier、overrides；名称可自定，支持多个方案 |

最终参数由公共基线加所选方案 overrides，再合入日常录制设置和方案曝光/增益组成。overrides 可覆盖允许的高级字段，使不同命名方案保留不同编码器、质量、帧率或其他维护参数；未覆盖的项继承 advanced.json。日常界面只显示本次解析后的帧率、分辨率和编码器，不提供直接编辑。

「保存并应用」修改当前方案曝光/增益并覆盖原值；「另存为新方案」复制当前方案的其他设置（包括高级覆盖），并采用页面当前输入的曝光/增益。若要保留原方案，填写新值后不要先保存覆盖，先停止预览，保留输入并填写新名称，再另存。切换已有方案也须先停止预览。不会因改名称自动校准画面，也不按环境亮度切换方案。一次录制开始后保存解析后的参数快照并锁定，所有分段均沿用；需换方案须停止、等待验证结束后重新开始。

## 详细画面与官方软件

「详细画面配置」提供白平衡色温与色调、gamma、contrast、brightness、hue、saturation、sharpening，以及四通道黑白电平。「保存画面配置」只写当前命名方案的 overrides.imaging，不修改 advanced.json 公共基线或其他方案。预览和录制使用相同的最终合并参数；保存时若预览运行，会停止并重新打开相机，应用设置并检查读回。录制及收尾期间禁止修改。

采集固定为全幅 8 位；额外降噪值保持原样，不通过此对话框调整。自动对焦不在软件功能范围，镜头仍需手动操作。

「打开官方录制软件」会先停止工作台预览，再以配套工作目录启动 64 位 ImageView；录制期间禁止启动。使用后须手动退出 ImageView 才能重新打开工作台相机。官方设置不自动同步到工作台，应在工作台配置方案并核对短录结果。

## 单位、编辑和验证

JSON 数值不加单位；布尔值用 true/false，不支持注释和尾逗号。保持对象结构、键名、方案 ID 与 daily.json 引用一致。exposure_ms 用毫秒，gain_multiplier 用倍数；旧 SDK 的 exposure_us 是微秒，gain 的 100 表示 1 倍，不能直接复制数字而忽略换算。

停机后备份 config/operator 整个目录，再编辑 JSON。配置应作为完整对象检查：不仅验证 JSON 语法，还验证最终合并后的取值范围、编码组合、保存路径与方案引用。出现错误先按提示修正，不通过删除客户配置或重新导入示例来绕过。页面未重新加载或仍显示旧值时，不要开始录制；确认本次页面摘要和最终参数快照一致。

当前采集链路仅支持 3840×2160；45 fps 对应 speed_level=4，30 fps 对应 speed_level=2。不要用 SDK 软件限帧替代硬件速度级别。当前录制编码器为 hevc_nvenc、h264_nvenc、libx265、libx264；H.264 路径要求 b_frames=0。

操作员指南约定 45 fps 日常曝光保持 12 毫秒，确需延长时最多 18 毫秒，调整光圈、增益和曝光后须短录核对。18 毫秒是操作上限，并非硬件上限或软件新增的强制校验；本次文档更新不改变客户已有方案。若需更短曝光来减少运动拖影，应由维护人员评估补光与噪声。光圈和对焦环位置不会保存在软件方案中，需另行标记。

质量模式中 NVIDIA 使用 nvenc_cq，CPU 编码器使用 crf；二者不能直接换算。capped_vbr 的码率设置与 quality 模式不同，不要只改数字而忽略 rate_control。GOP、B 帧、编码预设、队列、白平衡及其他成像项会影响性能或画质，改后必须用目标电脑、实际相机和保存盘试录。libx265 曾出现 4K45 吞吐不足，不能因为 NVENC 失败就假定 CPU 模式可直接替代。

## 预览与停止机制

浏览器预览上限约 2 fps、宽度不超过 960，不改变实际保存的帧率和分辨率。调参预览保存应用后，正式录制会关闭调参相机并重新打开同一设备，存在阶段间空隙；这不是连续无缝切换。录制时参数锁定。

关闭浏览器不停止录制；关闭后台 CMD 可能中断录制。使用停止按钮，等待写入与逐段验证结束。诊断以本次 capture.json、profile-used.json、continuous.ffmpeg.log 和页面所示的 process.log 为准，完整保存失败结果以便排查。短录结果不构成长时间无人值守或 72 小时保证。

## 更新与旧入口

使用小型更新 ZIP 时，按更新包中的「安装更新.cmd」操作，保留客户 config/operator/、旧配置原内容及匹配的 runtime/、sdk/、installers/。迁移清单 deprecated/migration-map.json 记录旧文件归档路径；不能以包内示例覆盖现场原值。不要把开发机 config/operator 覆盖到客户电脑。需要升级运行依赖时另行验证版本匹配，不以简单覆盖脚本代替迁移验证。

旧入口、配置和历史试录文档位于 deprecated/；旧菜单使用归档配置。根目录快速诊断默认解析工作台所选方案并保存诊断参数快照，不再默认读取旧 TOML；诊断仍不能替代实际画面试录。更新完成后运行软件包校验并进行新版界面一分钟试录、回看与参数快照核对，确认后逐步延长测试。

v2026.10.28 完整交付包合并本版工作台、完整运行依赖和累计升级入口。已有安装运行包中「升级现有安装/安装更新.cmd」，选择原工具包目录；新电脑直接使用完整副本。详细步骤见[客户下载与安装指南](客户下载与安装指南.md)。v2026.10.26 为旧工作流版本。

在线一键更新尚未实现。建议采用稳定 Release 的小型更新包加现有安装器；私有仓库下载身份、版本兼容及恢复机制见[一键更新可行性评估](automatic-update-feasibility.md)。不要在客户解压目录直接执行 git pull，也不要把个人访问令牌写进交付包。
