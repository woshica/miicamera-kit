# 2026-10-19 帧号跳变诊断与商家核实问题

本文记录本机实测与可复现的问题，不把帧号跳变直接归因为相机硬件故障。修正后本机已通过 **5 分钟 4K 45 fps 软件编码录像**：13,560 帧、45.2036 fps，零帧号缺口、零软件丢帧、零前后端溢出，各段提交与解码帧数一致。1 小时、24 小时稳定性尚未验证。详细范围见 [本机验证记录](local-verification.md)。

## 已确定的事实

1. 更换插口后，SDK 已报告 USB3；Windows 设备路径显示相机接在 Intel USB 3.20 控制器的根集线器上，没有下游外置集线器节点。
2. SDK 软件限帧不是硬件精确帧率设置。速度档位 2、`FRAMERATE=30` 时，本机源帧时钟约 30 fps，却只收到约 20 fps；设为 0 后恢复约 30 fps。工具已关闭这项软件限帧。
3. 45 fps 的帧号缺口伴随相机时间戳间隔翻倍：正常约 22,121 μs，缺口约 44,241–44,242 μs。采集时间轴确有缺口，不能仅把它视为显示帧号异常。
4. 采用原厂 C++ SDK 直接拉取图像，不使用 Python、不编码、不在采集循环写磁盘，仍可复现问题。两级缓冲各 16 帧、默认 USB 接收线程优先级 1 时，30 秒采集 1,352 帧，约 45.102 fps，有 2 个帧号缺口；SDK 软件丢帧、前后端缓冲满计数、错误事件均为 0。因而“软件丢帧计数为 0”不能单独证明源帧完整。
5. 默认前端 4 帧、后端 3 帧时，还会出现缓冲溢出。单独扩大前端缓冲消除了该次前端溢出，继续扩大后端缓冲消除了该次后端溢出，但仍有帧号缺口。把 USB block size 调为 50% 也未消除缺口。
6. 两级缓冲各 16 帧，在同样设置下仅将 SDK 的 USB 接收线程优先级由 1 改为 2 后，30 秒与 120 秒纯采集均为零跳帧、零软件丢帧、零溢出；120 秒采集 5,424 帧，约 45.207 fps。这是主机接收调度参与问题的证据，但还不能单独定位到驱动、SDK 或固件内部。
7. 原录像脚本每段结束都重新启动 FFmpeg，会阻塞编码线程。离线 45 fps 对照中，旧 NVIDIA 编码在 8 帧队列下溢出；改为单个 FFmpeg 进程连续分段后，软件编码和 NVIDIA 编码均完整写入并解码 225 帧，三段分别为 90、90、45 帧。离线静止画面测试不能代替实机录像。
8. 修正后已完成实机验证：软件编码 5 分钟、13,560 帧；NVIDIA 编码 60 秒、2,710 帧。两次记录都没有帧号缺口、软件丢帧、前后端溢出，各段解码帧数完全相符。软件编码那次全部相邻相机时间戳间隔为 22,120–22,121 μs，没有此前的翻倍间隔。

## 已实施的软件修正

- 30 fps 使用速度档位 2；45 fps 使用档位 4；关闭 SDK 软件限帧。
- 前、后端采集缓冲各 16 帧，SDK USB 接收线程优先级设为 2。该值是 SDK 定义的 `THREAD_PRIORITY_HIGHEST`，只影响本次相机运行中的接收线程；没有更改 Windows 电源方案或系统全局设置。
- 一个 FFmpeg 编码进程持续处理并分段，去掉每个分段之间关闭、重启进程的停顿。编码队列仍有明确上限，持续跟不上时停止并标记异常。
- 每帧保留相机帧号、相机时间戳和主机时间，并核对各段的提交帧数与解码帧数。异常不会被补帧或忽略。

分段按编码帧数计：例如目标 45 fps、60 秒一段，对应每段 2,700 帧。相机实际输出约 45.2 fps，视频按 45 fps 播放，两者时间会略有差别；实际采集时长以 CSV 时间戳为准。末段可以不足一个完整分段。

## 2026-10-26：ImageView NVIDIA编码失败（独立于早期USB问题）

已用只读运行时观察确认：ImageView 4.12.32549.20260908、RTX3070、610.88驱动，选择H.265／NVIDIA／质量100后，显卡匹配与NVENC会话打开成功；获取旧预设失败，随后自动软件回退。可另外向厂商转述以下信息，尚未发送：

> ImageView在 `nvEncGetEncodePresetConfig` 请求 `NV_ENC_PRESET_LOW_LATENCY_HP_GUID`（67082A44-4BAD-48FA-98EA-93056D150A58）时返回12／NV_ENC_ERR_UNSUPPORTED_PARAM，hevc_nvenc创建返回空后自动创建libx265。NVIDIA SDK13.1公告说明从590驱动起移除此预设支持，本机驱动610.88。请提供使用新预设／API的编码组件更新，并让界面明确报告实际编码器及回退错误。目前预览约45fps，软件回退的4K文件实际约22fps；相同电脑通过现代NVENC已验证45.2268fps、1355帧和零序号缺口。另请说明硬件路径成功运行时质量100对应的码率控制与targetQuality／QP，而非软件回退的CRF21。

依据：[NVIDIA弃用公告](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/deprecation-notices/index.html)。没有改动显卡驱动、厂商DLL或向商家发送测试视频。
