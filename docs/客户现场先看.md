# 客户电脑使用顺序

> 本文中的命令、配置和资源路径均相对于软件包根目录 `miicamera-kit/`；辅助入口在 `test/`，旧方案入口在 `test/legacy/`。

整套软件已准备好，可带到现场联调、试拍。请复制整个 `miicamera-kit` 文件夹，约2.1GB，保留内部目录；不要只复制几个CMD或ImageView主程序。无需安装Codex、Conda、Python或额外Python包，也不用复制本项目仓库。

## 到场后按此顺序

1. **复制到客户电脑本地磁盘**，例如 `D:/CameraKit`；不要在压缩包内运行。双击 **`test/校验软件包.cmd`**，结果应为 `failures: 0`。可编辑的TOML/JSON配置不做固定哈希，配置内容由下一步检查。
2. **连接与预览**：Windows 10/11 x64；相机通过随附USB3数据线直连电脑USB3口。双击 `test/启动相机工具.cmd`，选2检查型号、分辨率和USB连接。无法识别时查看 [驱动排查](drivers-and-troubleshooting.md)；原厂安装包已在 `installers/MIIImageViewSetup.exe`，需要安装时由现场管理员处理。不要先把全部安装包重复安装一遍。
3. 双击 **`打开官方录制软件.cmd`**，检查构图、机械对焦、光圈、亮度和日夜条件。若不是中文，在首选项中选Simplified Chinese并重启。开始脚本录制前，关闭ImageView的预览/录像，最好退出ImageView，确保相机只由一个程序使用。
4. **编辑 `录制参数.toml`**：设置保存盘、时长、曝光和增益等，然后双击 **`test/检查录制配置.cmd`**。初始模板为NVIDIA H.265、CQ30、p5、GOP250、B3、4K45，录1小时、每小时分段；实际以当前TOML和启动摘要为准。`output_dir = ""` 在独立迁移后保存到软件包旁的 `camera-recordings`；也可改为例如 `output_dir = "D:/MouseRecordings"`，不要把录像存进软件包。
5. **试录并回看**：双击 **`test/试录当前配置一分钟.cmd`**。它只临时覆盖为60秒/20秒分段，其余使用同一配置。完成后查看输出目录的 `capture.json`，`status` 应为 `complete`。把任意 `.mkv` 文件拖到 **`回看录像.cmd`** 上即可使用随包播放器回看，不依赖Windows额外安装H.265解码扩展；播放器内按Q或Esc退出。检查各段起止、运动清晰度、亮度和文件大小。
6. **开始正式时长**：确认后双击 **`启动录制.cmd`**。启动窗口会显示本次生效参数。按一次Ctrl+C可请求中止，等待收尾后再关窗口；中止会标记未完成。完整录满时还会逐段解码检查。每次自动建立新目录，不覆盖旧录像。逐帧索引、参数和日志与录像一起保留。

日常只用上述入口；其他“推荐配置”“H265”“官方参数CRF”等旧入口保留作对照，读取各自JSON，修改统一TOML不会改变那些旧入口。全部参数与CQ/CRF切换例子见 [录制参数说明](录制参数说明.md)。

## 到客户电脑先运行快速诊断

将整个软件包复制到客户电脑本地盘，连接相机USB3线，退出ImageView及其他录像程序。先在 `录制参数.toml` 中设置实际保存位置，然后双击 **`客户电脑快速诊断.cmd`**；也可从相机工具菜单选择17。通常约2～4分钟，慢电脑可能更久；无需管理员权限、联网、另装Python或FFmpeg，不会修改驱动、电源方案和原录制参数。

脚本检查Windows/CPU/内存、显卡与驱动、交流供电/电源设置、软件包完整性、保存卷文件系统/可用空间/小文件写入，以及SDK识别的相机、USB连接模式和4K分辨率。磁盘探针最多64MiB，仅删除自己新建的临时文件；空间不足10GiB时跳过写入，保留既有录像。若系统I/O卡住导致超时强制结束，可能留下一份 `.miicamera-disk-probe-*.tmp`，不要据此删除其他文件。

编码器不是只看显卡名称或FFmpeg列表：每种会实际编码小片，并逐帧解码确认。测试CPU H.264/H.265、NVIDIA NVENC、Intel QSV、AMD AMF。**当前录制工具可直接使用的只有 `libx264`、`libx265`、`h264_nvenc`、`hevc_nvenc`**；QSV/AMF即使测试通过，也仅说明硬件能力，尚未接入本录制工具。不存在对应硬件时显示不可用是正常结果。

对可用的四种录制编码器，再做45帧4K合成画面速度筛查；参数随当前配置，H.264候选B帧固定0，libx265候选固定CRF模式。速度包含启动和滤镜开销，不包含相机USB与本工具送帧路径，不能单凭这个数判定45fps实录已通过。相机/USB/保存盘及当前编码器条件满足时，随后自动按当前配置试录20秒、每10秒分段，保留当前曝光、增益、质量和预览设置；只有帧率、逐段解码、帧号及SDK丢帧检查均通过，才报告这次短录通过。它不会自动更换编码器或覆盖你的配置。

报告是 `report.txt`（中文说明）和 `report.json`（详细结果），还有每项测试日志及小型合成样片。独立迁移后的默认报告位置是软件包旁的 `camera-diagnostics/diagnostic-时间-编号/`；在本项目中位于 `private/qa/scratch/camera-pc-diagnostics/`。目录无写权限时报告退到系统临时目录，CMD会显示实际路径。相机试录保存在配置保存位置下的 `diagnostics/诊断编号/`，不会混入软件包或覆盖以前的录像。

结束码0表示当前配置20秒试录通过，1表示发现失败项，2表示实际试录未验证或用户中止；任何一种都不代表72小时验收。检测到其他相机/编码程序或无法确认占用时，脚本会跳过重负载与相机测试，不关闭它们。按一次Ctrl+C可中止诊断，已完成部分的报告仍保留。环境检查通过后，仍按下面流程用实际小鼠画面试录一分钟、回看画质，再逐步延长。

高级用法：在CMD中运行 `客户电脑快速诊断.cmd --skip-camera` 可只做电脑编码与SDK枚举检查，不实际录相机视频；`--output-dir "E:/MouseRecordings"` 可临时检查指定保存位置，不修改TOML。详细参数记录见报告中的 `profile` 和各编码器 `settings`。

## 边录边看

`启动录制.cmd` 和 `test/试录当前配置一分钟.cmd` 使用同一路采集流提供可选实时预览，不打开 ImageView，也不另开相机；启动前仍须关闭 ImageView 以释放相机。在根目录 `录制参数.toml` 的顶层设置 `preview_enabled = true` 即可启用。默认按5 fps、最大960像素宽度监看；可将 `preview_fps` 设为整数1～10、`preview_max_width` 设为整数320～1280，整数倍降采样后的宽度不超过上限。保存视频仍按所选配置执行，选择4K45时仍保存完整4K45视频。旧JSON未配置预览时默认关闭。

关闭预览窗口，或在该窗口按Q / Esc，只关闭预览，录制继续。停止录制须在录制CMD窗口按一次Ctrl+C，并等待写入收尾。完整录满时还会逐段解码验证。已经开始的旧进程不能补开预览，待本次结束后再启动。预览慢时只跳过预览帧，不保存原始帧文件；预览失败不会因此终止主录制。开启预览后的持续性能仍须现场试录验证。参数示例见 [录制参数说明](录制参数说明.md#录制时实时预览)，本机结果见 [预览验证记录](live-preview-validation.md)。

## CMD录制进度

两个统一入口可用根目录TOML顶层的 `status_enabled = true` 开启状态，`status_interval_seconds = 2` 设置刷新间隔（整数1～60秒）。CMD/Windows Terminal中同一块状态区原地刷新，不不断追加新行；上方配置及重要提示保留。状态包括已录/剩余时间、时间进度、实测fps、帧数、帧号缺口、编码队列、每帧写入耗时、MKV总量、可用磁盘空间、近期/平均近似Mbps，以及已生成、结束写入、当前和预计总计/还会新增的分段。窗口较窄时会换行；重定向为日志或不支持刷新时改为普通文本。状态由独立线程输出，采集线程不等待CMD输出。此更新下次启动录制生效。

录制时间100%后还有收尾写入和逐段验证，须看到最终“完成”并核对 `capture.json`；“未完成”的文件不代表通过完整解码验证。段数是估计，实测帧率略高于名义帧率时可能出现短尾段。码率按MKV增长估算、不含CSV，容器缓冲使近期值波动，并非精确编码器码率（约8 Mbps＝1 MB/s）。状态与预览配置均下次启动生效，不会热更新；拖动预览窗口大小只改变显示。详见 [录制参数说明](录制参数说明.md#cmd进度与容量状态)。
## 必须在客户电脑确认的条件

- **显卡驱动**：当前默认CQ方案需要能工作的NVIDIA编码器。客户提供的配置是RTX4060，但产品图片不能证明驱动已安装且兼容。包内没有NVIDIA显卡驱动安装器；如该机驱动有问题，需要现场联网获取适配驱动，或出发前由客户确认。不要因为编码失败就直接改为CRF21录4K45：该CPU路径在本机曾出现吞吐不足。
- **保存盘**：用于录像的盘应支持大文件，推荐本地NTFS；exFAT也支持大文件，FAT32不适合每小时分段。先前室内CQ30样片约11.6GB/小时，正式场景会变化，另需至少保留10GiB空闲空间。`max_recording_gb` 是按配置值触发的停止保护，不保证完整录满72小时，也不是精确的文件总量上限。
- **光学与成像**：初始对照用过曝光12ms、增益1016%（约10.16倍）、白平衡5468/1163；修改后以当前配置为准，需按现场照明重新确认，不是日夜通用设置。软件不会替代镜头对焦、光圈、支架固定或自动切换日夜参数。
- **持续性**：本机CQ30三分钟测试通过8135帧、45.21fps、零帧号缺口，已核对所有分段；之前也出现过一次编码队列溢出和一次采集缺帧，根因未全部确定。客户机仍须先短录，再逐步验证更长时长；不能直接作为已通过72小时无人值守验收的系统。录制时工具会阻止自动睡眠，不能防止断电或系统重启。
