相机录制工具包：客户下载与安装指南

本版交付包：miicamera-kit-v2026.10.28.zip。下载、解压后即可选择首次使用或更新已有安装。录制工作台在本机运行，日常录制不需要连接 GitHub。

仓库公开后的下载说明以这份独立指南和 Release 发布说明为准。为保持既有校验值不变，本轮不重打包 ZIP；ZIP 内附的早先指南仍写有私有访问要求，公开后下载已无需登录，其余安装步骤不变。

先选对操作

  • 新电脑、没有完整旧软件：使用压缩包中的 miicamera-kit/ 完整工具包，按下文「新电脑首次使用」操作。
  • 这台电脑以前已能录制，要保留原方案：使用 升级现有安装/安装更新.cmd，更新目标选择原来的工具包目录，按「已有安装更新」操作。
  • 原目录缺少 runtime/python/python.exe：不能用更新入口补齐环境。请使用完整包，并请维护人员协助迁移原设置；不要强行覆盖旧目录。

一、从 GitHub 下载完整交付包

  1. 打开浏览器。woshica/miicamera-kit 公开后，浏览发布页和下载软件附件无需登录 GitHub，也无需注册账号。
  2. 打开本版发布页：v2026.10.28 发布页。也可打开全部发布版本，选择负责人指定的版本。以页面实际附件为准；页面打不开或附件尚未列出时，先检查链接、版本标签和网络，再请交付人员核实附件。
  3. 在版本说明下方找到 Assets（附件），如为折叠状态，点击展开。点击 miicamera-kit-v2026.10.28.zip 下载完整包，再下载旁边与它同名的 .sha256 校验文件。两者放在同一个下载目录。
  4. 等浏览器显示下载完成。不要打开仍以 .crdownload、.part 结尾的临时文件。完整包约 952 MB，包含运行环境，需要完整下载；下载时间取决于现场网络，不要按几秒内必须完成来判断。
  5. 不要选择 Source code (zip)、Source code (tar.gz)，也不要点击绿色 Code 按钮里的 Download ZIP。这些是源码，不包含完整运行环境。客户不需要安装 Git、执行 git clone 或 git pull。
  6. 按下一节核对压缩包，再解压。下载本包无需提供账号密码或令牌。

GitHub 官方说明将发布附件与源码下载区分开来，参见下载 GitHub 文件和源码归档说明。

二、核对下载并解压

  1. 可请维护人员使用 PowerShell 核对 SHA-256。下面示例假设 ZIP 放在 D:/Downloads，请换成实际路径：
Get-FileHash -LiteralPath 'D:/Downloads/miicamera-kit-v2026.10.28.zip' -Algorithm SHA256
  1. 用记事本打开同版 .sha256，将命令输出的 Hash 与其中的 64 位摘要比较，字母大小写不影响比较。必须全部一致；不一致请重新下载，不要继续安装。若不熟悉操作，请让交付人员完成核对。
  2. 在 ZIP 上点击鼠标右键，选择「全部解压缩」，解压到独立目录，例如 D:/CameraDelivery-20261028。保留完整文件夹层级，不要在压缩包窗口内直接双击 CMD，也不要只拖出一个启动文件。
  3. 解压后应看到以下三项；资源管理器有时会额外套一层目录，以实际内容为准：
miicamera-kit/                 完整软件，含 runtime/、sdk/、installers/
升级现有安装/                  安装更新.cmd 和 miicamera-kit/ 更新内容
先读-客户下载与安装.html       本指南的离线阅读版

新电脑使用第一项；已有安装使用第二项。第三项可直接双击，用浏览器离线阅读。

三、新电脑首次使用

  1. 打开解压出来的完整 miicamera-kit/，确认其中能看到 runtime/、sdk/、installers/。不要移动其中的单个文件。
  2. 双击 test/校验软件包.cmd，确认检查通过。校验失败先保留提示，请交付人员排查。
  3. 连接相机、电脑电源及 USB3 线，关闭 ImageView 和其他占用相机的软件。双击根目录 客户电脑快速诊断.cmd，检查现场环境。新电脑如缺少相机驱动、显卡驱动或系统组件，由维护人员按诊断结果处理；完整包并不保证所有电脑无需配置就能录制。
  4. 双击根目录 启动录制.cmd。本地浏览器打开工作台后，保留后台 CMD 窗口。首次使用的模板仅提供起点，默认时长为 0.01 小时（36 秒），正式录制前必须改为实际需要的时长，并核对保存位置、分段和方案。
  5. 保存位置设为软件目录外的绝对路径，例如 E:/MouseRecordings，确认该磁盘存在且空间足够。「录制时长」单位为小时，「分段」单位为分钟。
  6. 在实际现场光照下点「打开预览」，核对构图、清晰度与亮度；选择并保存本次方案。首次使用或更改参数后，点「试录一分钟」，等待收尾与验证结束，再用 回看录像.cmd 回看保存的视频。
  7. 确认短录结果和参数正确后，再开始正式录制。结束时点击「停止并保存」，等待验证结束后再关闭后台窗口。短录通过不等于已经通过长时间连续录制验收。

日常细节见包内 docs/操作员上手指南.md 或 docs/operator-guide.html。

四、已有安装更新：保留客户原方案

  1. 先找到平时实际使用的旧工具包目录，例如 D:/Camera/miicamera-kit。记住这个位置，确认其中有 runtime/python/python.exe；它才是更新目标。不要把新下载的完整副本误当成旧目录。
  2. 若正在录制，点击「停止并保存」，等待写入和验证完成。停止预览，退出 ImageView，关闭工作台后台 CMD。仅关闭浏览器网页不会停止录制。保留原录像和现场日志。
  3. 将新 ZIP 解压到与旧工具包分开的目录。不要解压覆盖旧目录，也不要放进旧目录内。建议确认保存盘路径和原方案名称，便于更新后核对。
  4. 在新解压目录中打开 升级现有安装/，双击 安装更新.cmd。按提示输入旧工具包的完整路径，例如 D:/Camera/miicamera-kit。不要输入 升级现有安装/miicamera-kit，也不要输入新包中的完整软件副本。
  5. 等待显示更新完成。更新程序会先按 update-files.json 核验每个更新文件的 SHA-256、检查文件路径安全性，并确认相关程序未占用，再备份将要修改的文件，在原目录旁创建带时间标识的备份目录，并记录恢复清单。此备份针对更新涉及的文件，不是录像或整台电脑的完整备份，请保留它。
  6. 更新保留原 config/operator/ 配置。旧版本还没有该配置时，会先导入原根目录 录制参数.toml；两者都没有时才使用模板。旧入口和资料按迁移清单归档到 deprecated/，冲突的原文件保存在独立归档或备份中。旧 TOML 后续修改不会自动同步到新界面。
  7. 此更新只更换程序与说明等内容，保留旧安装的 runtime/、sdk/ 和 installers/。如需要升级这些依赖，须由维护人员另行确认匹配情况。
  8. 完成后，回到原工具包目录运行 test/校验软件包.cmd、客户电脑快速诊断.cmd，再双击原目录的 启动录制.cmd。核对原保存位置、时长、分段、选中方案和画面参数，再做一分钟试录、回看及结果验证。

不要启动新解压的完整软件副本后，期待它自动出现旧电脑的全部方案；两个目录各有独立配置。保留原桌面入口时，也应确认它指向已经更新的原目录。

五、「安装更新.cmd」究竟是什么

它是随交付包提供的 Windows 更新入口，内部调用本工具的 scripts/install-update.py，把本地更新内容安装到选定的已有工具包，备份被修改文件并保留现场配置。下载并解压好后，CMD 安装更新过程完全离线。

它按清单逐个覆盖累计代码更新包中的文件；不做二进制差分，也不按新旧版本差异联网下载。它不是 GitHub 客户端、相机驱动安装器或自动联网升级服务，也不是用于空白电脑的完整环境安装器。日常录制入口仍是 启动录制.cmd。installers/ 中的第三方依赖安装文件与这个更新入口用途不同，只有诊断确有需要时才由维护人员选择使用。

当前约 952 MB 的完整交付 ZIP 仍需完整下载。已有完整安装时，也可请维护人员另发不含运行依赖的累计代码更新包，减少传输量；它包含该版需要交付的代码文件，仍由本地 CMD 安装，不是自动增量更新。更新过程不改动 runtime/、sdk/、installers/。

更新报错时不要反复覆盖或删除客户配置。程序会尝试恢复本次修改，并输出恢复清单位置；若提示恢复不完整，请停止操作，将提示和清单路径交给维护人员。不要在未确认恢复结果时继续正式录制。

六、常见问题

  • GitHub 显示 404 / 页面不存在： 先检查链接是否完整、版本标签是否正确，再从全部发布版本页查找该版和 Assets 附件；同时确认现场网络能访问 GitHub。公开下载无需登录，仍有问题请交付人员核实发布状态。
  • 只看见 Source code： 先核对版本、Assets 是否展开；实际软件附件未列出时请联系交付人员，不要拿源码包替代完整包。
  • 网络慢、打不开 GitHub 或附件下载失败： 现场网络可能无法访问 GitHub，或能打开网页却无法下载 Release 附件。保持足够磁盘空间，重新下载并核对 SHA-256。无法完成时，可由交付人员提供已核验的本地 ZIP（如通过移动存储介质）或百度网盘等已确认渠道；使用同名、同版 ZIP 和校验文件，之后流程一致。本指南不提供尚未确认的网盘链接或提取码。
  • Clash 配置与下载网络： Clash 订阅配置可能包含订阅地址、令牌等凭据，不能公开上传到 GitHub、Release 或公开网盘，也不要放进软件包。网络设置请交现场网络维护人员处理。
  • 解压失败、缺文件或校验失败： 保留错误提示，重新下载并完整解压。不要从不同版本随意拼接文件。
  • 更新提示找不到 runtime： 重新检查是否选错目录；真正缺少运行环境时请走完整包首次使用流程，并由维护人员迁移原设置。
  • 更新提示程序未关闭或相机忙： 正常停止并保存，等待验证，关闭后台工作台和 ImageView 后再试。不要强行结束仍在写入的视频进程。
  • 新界面没有原方案： 检查是否启动了新副本；退出后从已更新的原目录启动。不要删除配置来试图恢复原方案。
  • 浏览器打不开、诊断失败或试录异常： 保存错误文字、诊断结果和本次录制日志，请维护人员处理。提供资料前确认其中不含账号凭据。

完成标准：下载摘要一致、软件包校验通过、现场诊断无未解决问题、正确目录启动、配置已核对、一分钟试录完成并回看通过。随后按现场安排逐步延长录制。
